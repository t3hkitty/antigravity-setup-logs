🔍 The "Parser Error on Install" Hit ListFor hybrid Capacitor/Cordova apps and native Kotlin engines, the package manager usually rejects an APK for four very specific reasons:1. **The Google Drive "Hot-Copy" Corruption (Most Common):**
  - **The Culprit:** Since your build script automatically copies finished builds directly into **G:\\My Drive\\myapks** \[cite: 101, 102\], the Google Drive desktop client immediately begins chunk-uploading the binary. If you download or copy the APK to your phone *before* that sync indicator turns solid green, the file on your device will be partially uploaded and corrupted.
  - **The Fix:** Wait for Google Drive Desktop to fully finish syncing the file before pulling it onto your test device.
2. **Signature & Package Collisions (No Clean Slate):**
  - **The Culprit:** If your device still has an older version of the app installed (such as an older package named `io.n8n.local.app`, `net.artkitty.myblackbox`, or a previous test build) \[cite: 42, 102\], the Android OS will block the installation of any new APK targeting the same namespace if it is signed with a different auto-generated debug certificate \[cite: 17, 264\].
  - **The Fix:** Manually **uninstall** any previous iterations of the app from your phone before attempting to install the fresh build \[cite: 150\].
3. **Android Minimum SDK Mismatches:**
  - **The Culprit:** Our native frameworks target **SDK 34 (Android 14)** with a minimum of **SDK 26 (Android 8.0)** \[cite: 234\]. If you are testing on an older device or an emulator running an Android OS below Oreo (SDK 26), the package parser will instantly throw an error.
  - **The Fix:** Ensure your test device meets the minimum SDK level \[cite: 234\], or have AGV adjust the `minSdk` attribute down inside `build.gradle.kts` \[cite: 235\].
4. **Malformed ****AndroidManifest.xml**** from Rapid Refactors:**
  - **The Culprit:** With our rapid feature additions (such as registering permissions for Bluetooth KVM diagnostic HUDs, Shizuku bindings, and Gutter Barks) \[cite: 6, 264, 285\], a duplicate permission string, a missing namespace, or an unclosed XML tag inside your `AndroidManifest.xml` can easily slip past Gradle compilation but trigger an instant parser failure upon Android installation.
  - **The Fix:** Have AGV validate the layout of the generated manifest to ensure every tag is properly balanced and structured.
